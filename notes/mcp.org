How team members get authorised to use the gfmrag MCP server (proxy to the
private =gfmrag-qa= Cloud Run service). Companion: notes/retrieval-mcp.org.

* Convention: per-user identity + run.invoker (via a Google Group)
A caller is authorised by: (1) authenticating as themselves
(=gcloud auth login them@tautsec.com=), (2) holding =roles/run.invoker= on the
=gfmrag-qa= service, (3) the proxy mints an ID token with THEIR identity +
the service URL as audience.
- Scalable form: a Google Group (=gfm-users@tautsec.com=) granted run.invoker
  ONCE on the service; authorise/deauthorise by group membership, one place to
  audit. Individual bindings fine for a handful.
- Service-scoped grant (not project-level) = least privilege.

** Two tiers
- =roles/run.invoker= -> broad (the group): can query.
- =roles/run.services.update= -> restricted (named individuals): can start/stop
  the service (the spending lever). NOT in the broad group.

* Manual path (GCP Console) — yes, supported
run.invoker grant:
1. Console -> Cloud Run -> =gfmrag-qa= (region us-central1).
2. Security / Permissions panel -> Add principal.
3. Principal = user/group email; Role = "Cloud Run Invoker" (=roles/run.invoker=).
4. Save.
(Service-scoped, least privilege. CLI equivalent above is preferred for
reproducibility.)
